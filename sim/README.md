# Independent simulation foundation

`voidfront_sim` is C++20 with no Godot dependency. Coordinates are integer 1/256 world units; one `step()` is exactly 1/20 second. The initial 32x24 map has two foundry ridges and three passages. Default setup is six walkers per side. Construct a new `Sim(seed,count)` to restart; 1..250 units per side are supported by the prototype spawn layout.

Submit commands for the current or a future tick before advancing it. IDs must exist and belong to the issuing player. Admission does not depend on unit health at receipt time; commands skip dead units at execution time. Submission sorts IDs; duplicate IDs are rejected. Positive sequence numbers are unique per player; tick order and sequence order must agree. Arrival order may vary. All commands execute in `(tick,player,sequence)` order. Pending commands, last applied sequences, RNG state and every authoritative unit field participate in an explicitly serialized FNV-1a state hash. This diagnostic hash is not a cryptographic integrity check. Since pending receipt state is included, future networking needs a separate executed-state checksum or an agreed command-receipt boundary before comparing these hashes.

The canonical command byte format is little-endian: magic bytes `56 46 43 01`, u32 tick, u32 sequence, u8 player, u8 order, u32 x, u32 z, u32 count, then count u32 IDs in strictly increasing order. Exact length, version, ID ordering, coordinate bounds, player/order values and list limits are validated before output is changed. Maximum list size is 256, future horizon 1200 ticks, pending queue 4096 commands. Protocol content negotiation and transport do not exist yet.

Move suppresses acquisition; attack-move acquires within six units and fires within three. Stop and hold both stand and fire within range. Stop takes effect without movement on its command tick; a unit stopped between grid centers retains its endpoint reservation, and a later move first resumes that edge. Movement is axis-aligned at 32 coordinate units/tick. Deterministic breadth-first routing includes moving endpoint reservations. Group orders choose distinct goal cells near the click. If the exact destination is inaccessible, routing approaches the nearest reachable cell. Damage is accumulated and applied after unit iteration, permitting mutual kills. Combat acquisition observes stable entity iteration and currently has side-dependent movement timing; balance requires further work.

`make_ai_commands` is only skirmish attack AI through the public command interface, not the completed economy/build/technology AI. Winner means the other side has no walkers; command anchors and the complete match loop are absent. There is no queued order, fog, dynamic structure blocking, high-quality local avoidance, hierarchical pathfinding, network lockstep, timeout, reconnect or desync report yet. Neither in-process decoded-command tests nor separate replay processes are networking evidence.

Standalone build: `cmake -S sim -B build/sim -G "Visual Studio 17 2022" -A x64`, then `cmake --build build/sim --config Debug -- /m:1` and `ctest --test-dir build/sim -C Debug --output-on-failure`; repeat Release. On this host normalize duplicate PATH/Path environment entries before CMake/MSBuild. The headless harness accepts `--ticks`, `--units-per-team`, `--seed`, `--trace`. It prints hash and p95/p99 wall-time microseconds for both the whole run and only ticks before victory; timing is measured outside authoritative code and includes AI/command work but excludes trace hashing/writes. Trace rows are tick plus state hash. Timing a small prototype map does not satisfy the 128x128 production performance gate.

Persist canonical inputs with `voidfront_headless --ticks 2000 --seed 42 --record match.vfr --trace original.trace`. A separate `voidfront_headless --replay match.vfr --trace replay.trace` process reads setup from the file and generates no AI inputs. Replay cannot be combined with explicit seed/unit-count/tick-count or recording. Commands are submitted at their recorded execution tick; this harness currently records only immediate AI commands and does not represent receipt timing of future network packets.

Replay container: bytes `56 46 52 01`, then little-endian u32 protocol version, seed, units per team, tick count, frame count. Each frame is u32 byte length followed by a canonical serialized command. Frames must be strictly ordered by tick/player/sequence, with ticks before the declared end. Limits: 64 MiB file, 100,000 frames, 1..250 units per team, 1..10,000,000 ticks, command size 30..1050 bytes. Exact frame count and end-of-file are checked, so truncation and trailing bytes fail. Header identity is protocol-only; production replays still need a content/build identity migration policy.

Process verification: `pwsh -NoProfile -File sim/verify_replay.ps1 -Executable build/sim/Release/voidfront_headless.exe -OutputDirectory build/sim/replay-evidence`. The script compares full record/replay traces, verifies empty-input playback has no AI, and requires nonzero exits for malformed headers, truncated frames, excessive limits, out-of-range command ticks, foreign ownership and trailing data. Repeat with Debug and compare configuration traces. These are separate file-playback processes, not a network transport test.
